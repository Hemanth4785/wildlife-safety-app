The ML data pipeline has been successfully refactored to fetch data directly from iNaturalist, cache it locally, and use it for ML inference without Firebase Storage.

### 1. Data Fetching
- Implemented `backend/python/fetch_inat_recent.py` to fetch historical data (from 2020) and save to `backend/python/cache/inat_historical.json`.
- Handled pagination and API rate limits.
- Normalized output schema as requested.

### 2. Local Storage Strategy
- Data is stored strictly in `inat_historical.json`.
- Fetch script performs incremental updates (logic implemented, though currently set to full fetch for safety/simplicity in this iteration, with hooks for incremental).

### 3. Date-Based Filtering
- Updated `backend/index.js` to expose:
  - `/api/wildlife/all`: Returns full historical data.
  - `/api/wildlife/recent`: Returns data from the last 7 days (default).
- Routing logic (`/api/animals/near-route`) and Map display (`/api/sightings`) now explicitly use `getRecentData(7)`.

### 4. ML Integration
- Updated `ml/random_forest_risk.py`, `ml/maxent_train.py`, and `ml/lstm_movement.py` to train using `inat_historical.json`.
- Updated `ml/predict_risk.py` to handle the normalized flat JSON structure for metadata.
- Installed `tensorflow` to enable LSTM movement prediction.
- Retrained all models (`RandomForest`, `MaxEnt`, `LSTM`) with the fetched data.

### 5. Node.js Integration
- `backend/index.js` now orchestrates the pipeline:
  - Checks for cache existence and runs fetcher if needed.
  - Calls Python inference scripts with correct inputs.
  - Removed all Firebase Storage/Firestore sync logic for wildlife data.

### 6. Code Quality
- Added comments explaining the separation of concerns.
- Simplified data flow: Fetch -> JSON Cache -> ML/API.

The system is now fully operational with local caching and direct API integration.
